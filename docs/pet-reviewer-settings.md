# 新学习屏桌宠：设置与媒体管理方案

评估日期：2026-10-08。配合[总体方案](pet-reviewer-feasibility.md)和[行为方案](pet-reviewer-behavior.md)阅读。下文为设置与媒体管理的设计记录。

模板配套迁移于 2026-10-08 完成；2026-10-09 恢复双构建，旧桌宠配置和代码仅用于原目录的有桌宠成品，`no_pets/` 下的无桌宠成品不包含它们。本文保留设置与媒体设计依据；应用功能源码已在相邻 Anki-Android 仓库实现，实机体验仍待验收。当前使用说明见[应用桌宠说明](../../Anki-Android/docs/development/reviewer-pets.md)，参数以应用实际实现为准。

用户指定：在“设置 → 新学习屏”中新增同级桌宠项，排在最下面、“相关设置”之前，只有开启新学习屏后才可启用；参数提供自定义入口；媒体按原模板分组结构分批添加、列表展示、按需启用。以下具体参数、默认值和导入细节均为设计建议。

## 1. 菜单位置与入口

建议将“桌宠”做成与“屏幕、复习、工具栏、回答按钮”同级的设置分组。主页面只增加三个条目，具体内容进入子页：

```text
设置 → 新学习屏
├─ 新学习屏总开关
├─ 屏幕
├─ 复习
├─ 工具栏
├─ 回答按钮
├─ 桌宠
│  ├─ 启用桌宠                 [开关]
│  ├─ 自定义参数               >
│  └─ 桌宠媒体                 >  已启用 1 组 · 7 个文件
└─ 相关设置
```

本地 [preferences_reviewer.xml](../../Anki-Android/AnkiDroid/src/main/res/xml/preferences_reviewer.xml) 已使用上述分组结构。在“回答按钮”的 `PreferenceCategory` 之后、`RelatedSettingsPreference` 之前新增桌宠分组即可；不放进“屏幕”内部。

“自定义参数”采用现有原生偏好子页；“桌宠媒体”采用设置容器内的列表页，文件较多时仍可方便管理。现有“工具栏操作”已经通过 `android:fragment` 打开自定义列表 Fragment；[Preferences.kt](../../Anki-Android/AnkiDroid/src/main/java/com/ichi2/anki/preferences/Preferences.kt) 负责设置容器和返回栈，这个模式可以复用。

参数、导入、预览与媒体管理均从设置进入。桌宠上的单击、双击、三连击和边框按住拖动继续承担已约定的动作，功能说明放在参数页的“操作说明”中。

## 2. 新学习屏和桌宠开关的关系

| 状态 | 桌宠分组 | 自定义参数和媒体入口 | 实际显示 |
| --- | --- | --- | --- |
| 新学习屏关闭 | 整组禁用 | 禁用 | 停止应用桌宠 |
| 新学习屏开启，桌宠关闭 | 总开关可用 | 可用，允许先配置素材和参数 | 隐藏 |
| 两个开关均开启 | 可用 | 可用 | 满足出现条件后显示 |

关闭新学习屏时保留桌宠开关值、参数和媒体组，不删除或重置；重新开启新学习屏后按保存状态恢复功能资格。开启桌宠只恢复资格，初始隐藏规则仍然有效。开关默认关闭，依赖未满足时摘要显示“先开启上方的新学习屏”。

[ReviewerOptionsFragment.kt](../../Anki-Android/AnkiDroid/src/main/java/com/ichi2/anki/preferences/ReviewerOptionsFragment.kt) 的 `setPrefsEnableState()` 已统一禁用其他设置，桌宠分组可沿用该逻辑。实际功能判断仍使用 `isNewStudyScreenEnabled && reviewerPetEnabled`。桌宠参数/媒体子页也检查此依赖，覆盖设置搜索和状态恢复等直接进入方式。

此方案采用用户手动打开新学习屏的流程，替代前一版“点击桌宠后弹窗同时开启两个开关”的建议。设置入口的改动因此更简单，桌宠注入和行为控制的实现范围相同。

## 3. 哪些参数适合自定义

建议参数页按“出现与提醒、外观与移动、边框”分组，再提供一个“高级设置”入口。常用数值同时提供预设和自定义输入；显示单位及当前值，修改后沿用现有设置的保存和返回方式。

### 常用参数

| 分组 | 参数 | 建议默认值 | 作用 |
| --- | --- | --- | --- |
| 出现与提醒 | 评分后飞过概率 | 10% | 人工“良好／简单”成功后抽取；0% 关闭评分飞过 |
| 出现与提醒 | 飞过冷却时间 | 30 秒 | 从实际开始飞过计时；冷却期间跳过 |
| 出现与提醒 | 停留提醒开关与时长 | 开启，60 秒 | 同一卡片前台有效停留过久时入场；关闭后仍可评分飞过 |
| 出现与提醒 | 三连击退场后再次出现 | 关闭 | 仅控制当前卡片；换卡恢复正常资格 |
| 出现与提醒 | 再次出现间隔 | 2 分钟 | 仅在上一项开启时可编辑，从手动退场开始计时 |
| 外观与移动 | 桌宠大小 | 100% | 相对默认尺寸缩放，提供素材预览 |
| 外观与移动 | 不透明度 | 100% | 调整可见程度，预览与复习使用相同数值 |
| 外观与移动 | 移动时长 | 2 秒 | 调整入场、换位、展开和飞过；退场使用相应短时长，不改变 GIF 自身播放速度 |
| 边框 | 双击收起比例 | 70% | 可选其他比例；始终保留可见、可点击的露出部分 |
| 边框 | 停留过久自动展开 | 开启 | 关闭时保持边框收起，仍可单击展开 |
| 边框 | 自动展开等待时长 | 60 秒 | 从收起完成或拖动松手重新计时，仅开启自动展开时可编辑 |

首次入场提醒与边框自动展开建议分开控制，两个等待时长默认都为 60 秒。这样长时间记忆的用户可以保留首次提醒、关闭自动展开，也可以单独调整展开频率。关闭首次提醒不强制改变边框自动展开开关，替代前一版将两者绑定的建议。

大小、不透明度、移动时长和收起比例提供有效范围；例如不透明度不能设成完全不可见，收起比例不能到 100%，点击区还需满足最小可操作面积。具体范围在实现时结合默认素材和窄屏调整，不在本次方案中固定全部数值。

### 高级参数

| 参数 | 建议默认值 | 说明 |
| --- | --- | --- |
| 收起边框偏好 | 最近一侧 | 自动／左／右；偏好侧无安全位置时仍允许避让到另一侧 |
| 无空位时的角落尺寸 | 正常尺寸的 60% | 提供缩小比例，角落仍受实际可见区域限制 |
| 内容避让距离 | 8 CSS px | 界面可提供“小／中／大”预设及自定义数值 |
| 移动曲线预设 | 渐停 | 默认沿用正常移动曲线；评分飞过使用匀速。用预设名称供选择 |
| 连击识别间隔 | 400ms | 可调整连击速度；单击执行等待也随之变化 |
| 拖动灵敏度 | 标准，约 8 CSS px | 用于区分点击和拖动，提供预设；小幅手指抖动不直接拖走 |

参数页提供独立预览区，可演示飞过、收起、展开和边框拖动；主动点“预览”才播放。预览不触发复习评分或改动会话提醒计时。“恢复默认参数”只重置参数，媒体组单独管理。

人工评分成功、初始隐藏、单击/双击/三连击动作、同卡计时规则和控件避让是交互规则。首期保持这些动作含义稳定；连击速度和拖动灵敏度作为高级参数适应不同用户。

## 4. 桌宠媒体：分组添加、列表启用

沿用原模板配置中 `pets[]` 的语义：每组具有 `name`、`enabled` 和 `files[]`。模板配置只用于有桌宠构建，应用使用独立清单保存这些数据。一次可以选择多个文件作为一组，也可以重复导入创建多组，或向已有组补充文件。应用内部另给组分配稳定 ID，重命名不会改变文件归属。

建议列表显示缩略图、组名、文件数和独立开关：

```text
桌宠媒体
暂无媒体组。添加自己的桌宠图片或动图后即可启用。
＋ 添加媒体组

[缩略图] 用户自定义的组名      [开启]
         4 个文件
```

- **点开关**：决定这组是否加入随机素材池。
- **点组名或整行**：进入组详情，预览文件、重命名、继续添加、移除文件和删除导入组。
- **点“添加媒体组”**：要求用户输入自定义组名，再打开系统文件选择器多选支持的图片/动图；导入确认页显示组名和文件列表，并提供“启用这组”开关。
- **组详情中的“添加文件”**：补充到同一组，保留原启用状态。

素材预览在设置页内完成；列表缩略图不同时播放全部 GIF。单个文件也能构成一组，组名由用户修改，界面不要求编辑 JSON 或填写应用私有路径。

### 随机选择的含义

迁移前的模板将所有启用组的 `files` 展平后等概率随机选图。首期按用户指定结构保留这个规则：**所有启用文件等概率，同时仍只有一只桌宠。** 例如两组分别有 7 和 3 个文件，对应组被选中的概率为 70% 和 30%。列表顺序不代表优先级。

新的一次隐藏后入场/飞过选取素材；已经驻留或收起时，翻面、换卡、换位和评分飞过保持同一素材。首期每个文件都可以参与这些动作，移动由应用动画完成，文件名中的 `fly`、`stand` 等不自动绑定动作。按动作指定素材和按组等概率/权重抽取可作为后续扩展，不作为导入要求。

### 空列表、禁用与删除

- 没有启用组或没有有效文件时，摘要显示“暂无可用媒体”，实际隐藏；总开关可保留，进入设置添加/启用组即可恢复资格。
- 用户创建的组可禁用或删除。删除组使用现有风格的确认对话框，说明包含移除该组的应用内副本。
- 个别文件导入失败时列出失败项并允许保留成功项；一项也未成功时不创建空组。取消选择或导入不改变已有组。
- 新文件复制到应用目录并可读取后，再更新清单；导入中断不会留下已启用但无法读取的清单条目。

## 5. 保存位置与回到复习后的行为

### 背景图、独立目录与卡片媒体库的比较

本地 [BackgroundImage.kt](../../Anki-Android/AnkiDroid/src/main/java/com/ichi2/anki/deckpicker/BackgroundImage.kt) 通过 `CollectionHelper.getCurrentAnkiDroidDirectory()` 定位目录，将背景图保存为根目录下的 `DeckPickerBackground.png`；[AppearanceSettingsFragment.kt](../../Anki-Android/AnkiDroid/src/main/java/com/ichi2/anki/preferences/AppearanceSettingsFragment.kt) 使用系统文件选择器取得图片。该文件不在 `collection.media` 中，背景图已有独立于卡片媒体的存储职责。

| 选择 | 职责与适配 | 建议 |
| --- | --- | --- |
| 沿用背景图选择/导入方式，桌宠用独立应用目录 | 由桌宠清单管理多组、多文件，能随应用设置跨牌组使用；原始文件位置变化不影响已导入副本 | 默认采用 |
| 类似背景图，在集合根目录下另建 `reviewer-pets/` | 同样能避开卡片媒体库，但媒体路径跟随集合目录，需要处理移动/切换集合时的路径与配置对应 | 需要用户直接管理目录时再考虑 |
| 放入 `collection.media` | 文件进入卡片媒体命名、检查与同步范围，桌宠启用清单仍需单独管理；应用资源与卡片资源的归属混合 | 新桌宠不自动扫描或读取其中遗留的模板文件 |

具体建议路径：

```text
用户导入：  context.filesDir/reviewer-pets/<groupId>/<文件ID>.<原扩展名>
媒体组清单：context.filesDir/reviewer-pets/manifest.json
```

不提供默认桌宠素材，所有资源由用户选择并导入。运行时通过应用 Context 取得目录，不硬编码设备绝对路径。组清单保存稳定 ID、组名、启用值、文件标识和原始显示名称；同名文件可以来自不同组。数字/开关参数按现有偏好方式保存，媒体清单由独立 repository 管理。GUI 与应用资源接口使用该清单，原模板的配置语义仅作为结构参考。

系统选择器只是取得源文件的入口；导入时将原始字节复制到桌宠目录，保留图片/GIF 格式。可以复用通用选择、读取和复制工具，但桌宠增加自己的多文件结果处理、验证和清单更新。`BackgroundImage.import()` 的目标是固定单张背景文件且会修改背景开关，不适合直接用来保存桌宠。

WebView 通过限定的 `/reviewer-pets/<groupId>/<fileId>` 资源地址读取导入素材，由原生资源处理器解析清单并映射到应用文件。注入脚本使用这个资源地址，用户不需要操作私有目录或将绝对路径写进模板。自定义素材不会自动进入 Anki 卡片媒体同步；后续迁移设备时，可扩展桌宠包导入/导出。

### 回到复习后应用配置

返回复习时读取最新配置并重新测量。只调整参数不会把隐藏桌宠立即唤出；关闭总开关取消动作并隐藏。当前素材所属组仍有效则继续使用；被禁用/删除时改选其他可用素材，保持原驻留/边框模式并重新测量，无可用素材则隐藏。边框自动展开开关或时长改变时，重新开始完整等待，避免刚离开设置就立即展开。

## 6. 对项目的改动范围

菜单位置和新学习屏依赖可以直接沿用现有模式。主要新增工作是参数页和预览、媒体组列表/详情、多文件导入、媒体清单存储，以及独立资源读取。它们集中在原生设置与桌宠资源管理中，模板仍无需新增入口或传递代码。

建议实施时分开提交：设置与配置模型、媒体组管理与导入、复习页应用配置。总体方案中原先的约 12–16 个文件估算只涵盖基础设置和桌宠注入，未包含本轮完整的媒体组管理，不能当作当前全部功能的文件数上限。
